\section{Memory-Mapped GPIO}
\label{sec:gpio}

PC13 was configured as a push-pull output and toggled using explicit
\reg{volatile} pointers built from addresses in RM0091~\cite{rm0091}, without
any HAL GPIO function. Each register address is the peripheral base address plus
the register offset, $A = B + O$ (\cref{tab:gpio-addr}). The build checks every
address against the CMSIS device header with \reg{\_Static\_assert}.

\paragraph{Choice of output register.}
PC13 is toggled with a read-modify-write (\texttt{\^{}=}) on \reg{GPIOC\_ODR}. The
alternative is to read ODR and then write BSRR (set) or BRR (reset), which is a
single atomic write. The ODR read-modify-write is safe here because no interrupt
or other code writes to GPIOC, so nothing can change ODR between the read and
the write, and \texttt{\^{}=} is the simpler implementation. BSRR is used for the
starting level, where a single write suffices.

\paragraph{Why \texttt{volatile}.}
A peripheral register can change, or react to being accessed, independently of
the program flow. \texttt{volatile} forces the compiler to perform every read and
write to the register address exactly as written, instead of keeping a copy in a
CPU register or removing accesses it considers redundant. Without it, repeated
writes to ODR in the loop could be optimised away, so PC13 would never toggle.

\paragraph{GPIO clock disabled.}
If IOPCEN is never set, GPIOC is not clocked: writes to its registers (MODER, ODR,
BSRR) have no effect and reads return 0, so PC13 stays in its reset state (input)
and never toggles.
