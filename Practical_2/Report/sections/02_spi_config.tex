\section{Hardware SPI Configuration}
\label{sec:spi-config}

The EEPROM is driven by the STM32 hardware SPI peripheral, configured entirely
through its registers in \reg{eeprom\_spi\_init()}; no HAL/LL SPI functions or
CubeMX configuration are used.

\paragraph{Pin mapping.}
The handout's pin table (PB13 = SO, PB14 = SI, PB15 = SCK) cannot be correct:
the STM32F051 fixes the SPI2 functions on these pins in silicon
\cite[Tab.~15]{stm32f051ds}. The mapping in the Practical~2
README~\cite{readme} was therefore checked by continuity, with the board
unpowered and the P2 loopback jumpers removed. EEPROM pins 8 (VCC) and 4 (VSS)
were checked against 3V3 and GND first, to confirm the pin numbering
\cite[p.~1]{eeprom}. The measured mapping (\cref{tab:pins}) agrees with the
README and with the AF0 column of \cite[Tab.~15]{stm32f051ds}.

\paragraph{SPI clock calculation.}
\reg{SystemClock\_Config()} selects the 8~MHz HSI oscillator as SYSCLK with the
PLL off \cite[\S6.2.2]{rm0091}, and sets both the AHB (HPRE) and APB (PPRE)
prescalers to $\div$1 \cite[\S6.4.2]{rm0091}. SPI2 lies on the APB bus
\cite[Tab.~1]{rm0091}, and APB peripherals are clocked by PCLK
\cite[\S6.2]{rm0091}, so $f_\mathrm{PCLK} = \PCLKHz$~Hz. The BR[2:0] field of
\reg{SPI\_CR1} divides PCLK by $2^{\mathrm{BR}+1}$ \cite[\S28.9.1]{rm0091}:
\begin{equation}
  f_\mathrm{SCK} = \frac{f_\mathrm{PCLK}}{2^{\mathrm{BR}+1}}
                 = \frac{8~\text{MHz}}{2^{\BRDec+1}}
                 = \frac{8~\text{MHz}}{\BRDivider}
                 = \fSCKPred~\text{kHz}.
  \label{eq:sck}
\end{equation}
The required ratio $8~\text{MHz}/250~\text{kHz} = 32 = 2^5$ is exactly one of the
available divisors, so BR = \texttt{\BRBits} gives 250~kHz with no rounding. The
value was calculated, not tuned: a \reg{\_Static\_assert} in \reg{main.c} fails the
build unless the predicted frequency is exactly 250~kHz.

\paragraph{Alternate functions and chip select.}
MODER on its own only hands a pin to ``a peripheral''; the 4-bit AFSEL field
selects which one. For pins 8--15 this field is in \reg{GPIOx\_AFRH}
(\reg{AFR[1]} in the CMSIS header), so PB13--PB15 use AFSEL13--15 = AF0.
PB12 is not given to SPI2: chip select is driven by software so the driver
controls exactly where each EEPROM transaction starts and ends. CS is active
low, so it is held high from start-up to keep the EEPROM deselected while the
bus is configured and while the Task~3 test byte is sent; the output level is
written before the pin becomes an output so that it never glitches low.
