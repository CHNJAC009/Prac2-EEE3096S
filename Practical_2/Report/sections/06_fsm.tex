\section{Non-Blocking FSM}
\label{sec:fsm}

The Task~4 transaction was restructured as a deterministic finite state machine,
\reg{update\_eeprom\_state\_machine()}, called once per pass of the main loop
between \reg{read\_inputs()} and \reg{update\_outputs()}. PA0 starts a
transaction and PA3 aborts it.

\paragraph{Transition logic.}
\writeup{Short description: what starts a transaction, how the busy state schedules the next status check with HAL\_GetTick(), how completion is decided from the status register, what happens on timeout (never ready), how abort leaves the SPI bus and CS, and what the status LEDs show in each case.}

\paragraph{Why the implementation is non-blocking.}
\writeup{Each call does a bounded amount of work (at most one short SPI transaction) and returns; no HAL\_Delay or busy-wait for the internal write cycle. Support with evidence, e.g. the PC13 heartbeat continuing during a write with ee\_use\_fsm = 1 but stalling with ee\_use\_fsm = 0, and PA3 being honoured mid-transaction.}
